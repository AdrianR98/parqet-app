# Parqet Pipeline Inventory

Status: Phase 2 research inventory

Scope: Refs #248, Fixes #249

## Purpose

This document inventories the current Parqet data pipeline, route/read-model boundaries and replacement-gate evidence needed before the isolated Global Asset pipeline may feed or replace product routes.

This is structural documentation only. It does not authorize runtime changes, route migration, Global Asset product integration, new provider calls, OAuth/token changes, durable storage, deletion of existing calculation paths or private-data access.

## Classification Terms

Provider-call classification:

- `provider-backed`: the path can directly call Parqet or refresh Parqet tokens when invoked.
- `snapshot-first`: the path prefers an existing server snapshot or local cache, but can call Parqet only through an explicit refresh/load path.
- `snapshot-only`: the path reads an existing server snapshot and must not call Parqet.
- `browser-local`: the path reads or writes browser-local state only.
- `no data call`: the path has no provider, snapshot or browser data read/write behavior.

Replacement status:

- `canonical`: current source-of-truth boundary for its stated responsibility.
- `compatibility`: current product or bridge path that should remain until a migration is proven.
- `candidate-for-migration`: likely future replacement target after gate evidence exists.
- `deprecated-candidate`: current path with provider-call, privacy or duplication risk that should be retired or replaced when safe.
- `keep`: supporting path that should continue, subject to normal hardening.

## Hidden Provider-Call Risks

- `src/app/api/parqet/portfolios/route.ts` is provider-backed and is loaded on Dashboard mount. It does not fetch Activities, but it is still a provider call.
- `src/app/api/parqet/activities/route.ts` is provider-backed without snapshot reuse or an explicit `refresh=1` guard. Tracked-file search found no active consumer, so reuse would be a regression risk.
- `src/app/api/parqet/assets/audit/route.ts` calls `buildActivityContext(..., { refresh: true })` whenever invoked. Asset-specific audit opens can therefore trigger broad Activity fetches.
- `src/app/api/parqet/assets/route.ts` is snapshot-first, but the Dashboard explicit load path always sends `refresh=1`. That is intentional user-triggered refresh behavior, not a local navigation path.
- `src/app/api/parqet/global-assets/audit/route.ts` defaults to snapshot/no-provider behavior, but when `refresh=1` is used, output flags such as `includeAssets=false`, `includeActivities=false`, `isin` or `limit` reduce response size and local output scope, not necessarily upstream provider calls.
- Token refresh helpers are provider-backed. They should only run for likely auth failures, not generic pipeline or rate-limit failures.

## Raw And Private Data Risks

- Provider routes handle private portfolio ids, portfolio names, activity ids, activity amounts, holdings context and account structure. Route responses must remain projected and redacted.
- Server snapshots hold private activity-derived data in memory. They are bounded and non-durable, but still private.
- Browser Dashboard cache holds private derived read models in `localStorage`. It is suitable for v1 local reuse, not durable production persistence.
- Report CSV/Markdown exports are browser-local, but they can contain private derived portfolio/asset metrics and must export only visible safe read-model fields.
- Override stores can contain private activity ids, match criteria or real local decisions. Real local override decisions must not be committed.
- Debug logging around overrides and Dashboard missing metadata/warnings should be reviewed before any broader productization.
- Local audit outputs, cookies, `.env*`, OAuth codes, tokens, private exports, real portfolio/depot/activity data and raw provider payloads must stay out of repository files, issues, PRs and screenshots.

## Replacement Gate Evidence Checklist

Every later route/read-model migration issue must satisfy this checklist before implementation:

- [ ] Route-specific Sub-Issue exists and links back to #248 and the relevant replacement target.
- [ ] Old/new output comparison plan exists for the exact route/read-model.
- [ ] Synthetic fixture comparison path exists, or a justified follow-up exists before product replacement.
- [ ] Local real-data audit comparison stays local and is summarized only with redacted/count-only evidence.
- [ ] Provider-call behavior is classified as `provider-backed`, `snapshot-first`, `snapshot-only`, `browser-local` or `no data call`.
- [ ] API Budget Impact documents request count/scope, cache or snapshot reuse, retry behavior, rate-limit behavior, hidden reload risk and explicit refresh semantics.
- [ ] Privacy/Data Impact documents private fields handled, redaction boundaries, diagnostics/log/export behavior and local-only evidence rules.
- [ ] Source, freshness, confidence, warnings and blocked-metrics handling is reviewed for each displayed/calculated metric.
- [ ] Rollback steps are documented.
- [ ] Old path/compatibility projection retention or feature-flag decision is documented.
- [ ] Docs, changelog and ADR impact are reviewed.
- [ ] No broad UI/UX redesign is included.
- [ ] No old calculation path is deleted until the replacement is verified and rollback is clear.
- [ ] No new provider call behavior is introduced without explicit issue-level authorization.

## First Migration Candidate

No canonical Global Asset-backed production route/read-model migration is ready yet.

The inventory shows that the current Dashboard asset path owns user-visible cost basis, average buy price, position value, unrealized PnL, active/closed status, report totals and browser-cache contracts through `src/app/api/parqet/assets/route.ts`, `src/lib/parqet-assets/build-corrected-assets.ts` and `src/lib/dashboard-cache.ts`. The canonical Global Asset aggregation is intentionally preliminary: it has normalized activities, timelines, portfolio breakdowns, quantity effects, dividend/fee/tax totals, warnings, confidence and unresolved decision candidates, but it does not implement cost basis, market value, unrealized PnL, transfer pairing, metadata enrichment, FX conversion or a product read-model/cache contract.
